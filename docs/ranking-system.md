# Semantic Reranking System

## Overview
The system uses a deterministic two-stage retrieval and reranking pipeline.

1. **Retrieval**: Qdrant vector index is queried using Cosine similarity. We fetch an expanded candidate pool (`retrieval_k = 50`).
2. **Resolution**: The candidate IDs are queried against PostgreSQL to hydrate the authoritative `Asset` models.
3. **Scoring**: A pure deterministic heuristic scores each asset on 3 components: Semantic relevance, Resolution, and Orientation.
4. **Tie-Breaking**: Candidates with identical final scores are sorted deterministically based on raw values.

## Scoring Weights

- **70% Semantic Score**: Pure visual-textual relevance (normalized [0.0, 1.0]).
- **15% Resolution Score**: A tiered system that heavily rewards 4K+ while keeping 1080p competitive.
- **15% Orientation Score**: Rewards matching the requested aspect ratio (landscape/portrait/square).

### Resolution Tiers
- **4K+ (>= 8MP)**: 1.0
- **1080p+ (>= 2MP)**: 0.9
- **720p+ (>= 1MP)**: 0.7
- **< 720p**: 0.3
- **Unknown**: 0.0

### Orientation Tiers
- **Exact Match** (or requested "all"): 1.0
- **Partial Match** (e.g. square vs landscape): 0.5
- **Mismatch** (e.g. portrait vs landscape): 0.0

## Tie-Breaker Sequence
If two assets have the exact same `final_score`, we deterministically break ties using the following sequence:

1. `final_score` (Descending)
2. `semantic_score` (Descending)
3. Total `pixels` (Descending)
4. `provider_name` (Ascending / Alphabetical)
5. `provider_asset_id` (Ascending / Alphabetical)

## Multi-Query Handling
When processing multiple visual queries for a single scene (e.g. generated by Gemini), the system uses **Max Pooling**.
1. We retrieve 50 candidates for each query individually.
2. We combine them into a single pool.
3. If an asset is found by multiple queries, we retain its **highest** semantic similarity score.
4. The deduplicated pool is then scored and ranked deterministically.
